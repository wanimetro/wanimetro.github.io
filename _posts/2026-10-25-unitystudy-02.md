## 1. 10/8 세션

이번 스터디에서는 오브젝트에 상태와 시간의 흐름을 추가하는 방법을 학습했다.

사실 이 세션에서 내가 맡은 부분을 정리한 파일이 사라져서;; 이번에는 간단히 개념만 짚고 넘어가려고 한다…

### FSM (Finite State Machine)

FSM은 **유한 상태 머신**으로, 오브젝트가 가질 수 있는 상태와 상태가 전환되는 조건을 정의하는 방식이다.

예를 들어 NPC가 가만히 있다가 이동하고, 플레이어를 발견하면 공격하는 행동을 구현한다고 해보자.

이때 각각의 행동을 상태로 나누고, 특정 조건에 따라 상태를 변경하도록 만들 수 있다.

FSM은 크게 두 가지 요소로 구성된다.

- **State(상태):** 오브젝트가 현재 수행하는 행동이나 상황
- **Transition(전이):** 특정 조건에 따라 다른 상태로 변경되는 과정

상태별로 동작을 구분할 수 있기 때문에 여러 행동을 가진 오브젝트를 관리할 때 유용하다.

### Animation & Animator

Animation은 오브젝트의 움직임이나 속성 변화를 시간에 따라 표현하는 기능이다.

Unity에서는 Animation Clip과 Animator Controller를 이용해 애니메이션을 관리할 수 있다.

- **Animation Clip:** 개별 애니메이션 동작을 저장한 데이터
- **Animator Controller:** 애니메이션 상태와 전환 조건을 관리하는 컨트롤러
- **Parameter:** 애니메이션 전환 조건을 제어하는 값
- **Transition:** 애니메이션 상태 사이의 전환

특히 Animator의 Parameter를 이용하면 스크립트에서 애니메이션 전환을 제어할 수 있다.

### Coroutine

Coroutine은 **작업을 여러 프레임에 걸쳐 나누어 실행할 수 있도록 하는 기능**이다.

일반적인 함수는 실행되면 순서대로 코드를 처리하지만, Coroutine은 실행 도중 일정 시간 기다리거나 다음 프레임까지 실행을 미룰 수 있다.

대표적으로 다음 세 가지를 사용한다.

- `IEnumerator`: Coroutine을 작성할 때 사용하는 반환 형식
- `yield return`: Coroutine의 실행을 일시 중단하고 이후에 재개
- `WaitForSeconds`: 지정한 게임 시간만큼 대기

예를 들어 다음과 같이 작성할 수 있다.

```csharp
IEnumerator WaitExample()
{
    yield return new WaitForSeconds(2f);
    Debug.Log("2초 경과!");
}
```

이 Coroutine을 실행하면 약 2초가 지난 후 로그가 출력된다.

Coroutine은 일정 시간 후 상태를 변경하거나, 특정 효과를 일정 시간 동안 유지하는 등의 기능에 활용할 수 있다.

### Object Pooling

Object Pooling은 **오브젝트를 필요할 때마다 새로 생성하는 대신, 미리 생성해 두었다가 재사용하는 방식**이다.

Unity에서는 `Instantiate()`로 오브젝트를 생성하고 `Destroy()`로 제거할 수 있다.

하지만 오브젝트를 반복적으로 생성하고 제거하면 메모리 할당과 해제, 가비지 컬렉션 등에 따른 성능 부담이 발생할 수 있다.

Object Pooling은 이러한 문제를 줄이기 위한 방법 중 하나이다.

**기존 방식**

```text
오브젝트 생성
     ↓
오브젝트 사용
     ↓
오브젝트 제거
     ↓
필요할 때 다시 생성
```

**Object Pooling 방식**

```text
오브젝트 미리 생성
     ↓
비활성화 상태로 보관
     ↓
필요할 때 활성화
     ↓
사용 후 비활성화
     ↓
다시 재사용
```

## 2. 실습 과제: FSM으로 움직이는 NPC 만들기

이번 과제에서는 기존 오리 플레이어와 **스스로 움직이고 플레이어의 움직임에 반응하는 NPC 오리**를 구현했다.

게임프로그래밍 수업에서 게임 속 캐릭터의 행동에 대해 배웠던 것이 생각났다. 단순히 정해진 움직임을 반복하기보다, 상황에 따라 행동이 달라지는 NPC를 만들어 보고 싶었다.

### 2-1. Idle → Wander → Attack

먼저 NPC가 세 가지 상태를 가지도록 FSM을 구현했다.

- **Idle:** 가만히 대기하는 상태
- **Wander:** 플레이어를 향해 이동하며 거리를 좁히는 상태
- **Attack:** 플레이어가 일정 거리 안으로 들어왔을 때 공격하는 상태

NPC는 플레이어와의 거리에 따라 상태를 전환하도록 구현했다.

Wander 상태에서는 플레이어 방향으로 이동하며 거리를 좁히고, 플레이어가 공격 범위 안으로 들어오면 Attack 상태로 전환된다.

공격이 끝나면 Idle 상태로 돌아가고, 일정한 쿨다운이 지난 뒤 조건에 따라 다시 공격하거나 이동한다.

**NPC의 기본 행동 흐름**

```text
       Wander
          │
    플레이어에게 접근
          │
    공격 범위에 진입
          ▼
        Attack
          │
       공격 종료
          ▼
         Idle
          │
   쿨다운 및 거리 확인
          │
          ├── 공격 범위 안 → Attack
          │
          └── 공격 범위 밖 → Wander
```

이렇게 상태를 구분하니 NPC가 현재 어떤 행동을 해야 하는지 관리하기 편리했다.

특히 플레이어와 NPC 사이의 거리를 이용해 공격 상태로 전환되는 조건을 설정했다.

### 2-2. 플레이어 방향으로 회전하기

NPC가 플레이어를 바라보도록 만들기 위해 두 오브젝트의 위치 차이를 이용했다.

```csharp
Vector3 direction = player.position - transform.position;
```

플레이어의 위치에서 NPC의 위치를 빼면 **NPC에서 플레이어를 향하는 방향 벡터**를 구할 수 있다.

이 방향을 이용해 NPC가 플레이어를 바라보도록 회전시켰다.

실제 구현에서는 높이 차이에 의해 NPC가 위아래로 기울어지지 않도록 방향 벡터의 `y`값을 0으로 설정했다.

```csharp
Vector3 offset = player.position - transform.position;
offset.y = 0f;
```

이후 `Quaternion.LookRotation()`과 `Quaternion.RotateTowards()`를 활용해 NPC가 플레이어 방향으로 부드럽게 회전하도록 구현했다.

따라서 플레이어가 NPC의 어느 방향에 있더라도 NPC가 플레이어를 향해 이동하고 공격할 수 있었다.

### 2-3. Animator로 공격 애니메이션 적용하기

상태에 따른 행동을 구현했다면, 다음은 그 행동이 눈에 보이도록 애니메이션을 연결해야 했다.

이번에는 Animator의 Trigger Parameter를 사용해 공격 애니메이션이 실행되도록 했다.

```csharp
animator.SetTrigger("attack");
```

현재 공격 동작은 **NPC 오리가 점프하는 형태**로 표현했다.

NPC가 Attack 상태로 전환되면 플레이어를 바라보면서 공격 애니메이션을 실행한다.

### 2-4. Object Pooling으로 공격 이펙트 관리하기

공격 애니메이션에 이어 시각적인 피드백도 추가하고 싶었다.

그래서 NPC가 공격할 때 폭발 파티클 이펙트가 나타나도록 구현했다.

처음에는 `Instantiate()`를 사용해 공격할 때마다 이펙트를 생성했는데, 이후 Object Pooling 방식으로 변경했다.

`EffectPool` 스크립트를 만들어 폭발 이펙트를 관리했다.

게임이 시작될 때 폭발 이펙트 5개를 미리 생성하고, 비활성화 상태로 보관하도록 했다.

이펙트는 Queue를 이용해 관리했다.

**구현 흐름**

```text
게임 시작
   │
   ▼
폭발 이펙트 5개 미리 생성
   │
   ▼
비활성화 상태로 Queue에 보관
   │
   ▼
NPC 공격 발생
   │
   ▼
Queue에서 이펙트 꺼내기
   │
   ▼
이펙트 활성화 및 재생
   │
   ▼
일정 시간 후 비활성화
   │
   ▼
Queue에 다시 반환
```

이렇게 구현하면 공격할 때마다 새로운 이펙트를 생성하지 않고 기존 오브젝트를 재사용할 수 있다.

## 3. 10/12 세션: ScriptableObject와 UI

이번 세션은 Unity Basic의 마지막 회차였다.

지금까지 구현한 이동, 상호작용, FSM에 ScriptableObject와 UI를 연결해 프로젝트를 정리하는 것이 목표였다.

이번에 학습한 주요 개념은 다음과 같다.

| 개념 | 역할 |
|---|---|
| ScriptableObject | 여러 오브젝트에서 참조할 수 있는 설정 데이터 관리 |
| Canvas & RectTransform | UI 요소 배치 및 화면 크기에 따른 위치 조정 |
| Layout Group & TextMeshPro | UI 요소 정렬 및 텍스트 표시 |
| Button & UI Event | 사용자 입력과 함수 연결 |
| UI State & Game Logic | 게임 상태 변화에 따라 UI 갱신 |

### ScriptableObject

ScriptableObject는 **게임에서 사용하는 데이터를 별도의 Asset으로 저장하고 관리할 수 있도록 하는 기능**이다.

일반적으로 MonoBehaviour는 GameObject에 부착되어 동작을 처리하는 데 사용하지만, ScriptableObject는 GameObject에 부착하지 않고도 데이터를 저장하고 참조할 수 있다.

예를 들어 여러 NPC가 동일한 이동 속도나 공격 범위 등의 설정값을 사용한다면, 각각의 스크립트에 값을 저장하는 대신 하나의 ScriptableObject를 공유하도록 만들 수 있다.

또한 설정값이 스크립트와 분리되기 때문에 코드를 직접 수정하지 않고도 Inspector에서 값을 변경할 수 있다는 장점이 있다.

현재 체력이나 점수처럼 실행 중 계속 변하는 값보다는 캐릭터의 기본 능력치나 아이템 정보처럼 **공통으로 사용하는 설정 데이터**를 관리하는 데 유용하다.

### Canvas & RectTransform

Canvas는 Unity에서 UI 요소를 배치하고 렌더링하기 위한 기본 공간이다.

Unity의 UI는 일반적으로 Canvas 아래에 배치되며, Canvas의 Render Mode에 따라 화면에 표시되는 방식이 달라진다.

대표적인 Render Mode는 다음과 같다.

- **Screen Space - Overlay:** UI를 화면 위에 직접 표시
- **Screen Space - Camera:** 지정한 카메라를 기준으로 UI 표시
- **World Space:** UI를 3D 공간 안에 배치

RectTransform은 UI 요소의 위치와 크기를 조절하는 컴포넌트이다.

일반적인 Transform과 달리 Anchor와 Pivot을 이용해 화면 크기나 부모 UI의 크기가 변경될 때 요소가 어떻게 배치될지 설정할 수 있다.

### Layout Group & TextMeshPro

Layout Group은 여러 UI 요소를 일정한 규칙에 따라 자동으로 정렬하는 기능이다.

대표적으로 Horizontal Layout Group, Vertical Layout Group, Grid Layout Group 등이 있다.

TextMeshPro는 Unity에서 텍스트를 표시할 때 사용하는 기능으로, 글꼴이나 크기, 정렬, 색상 등을 설정할 수 있다.

특히 UI에 표시되는 텍스트가 길어지거나 요소의 개수가 달라지는 경우, Layout Group과 TextMeshPro를 함께 활용하면 UI를 관리하기 편리하다.

### Button & UI Event

이번 스터디에서는 내가 **Button과 UI Event**에 대한 개념 설명을 맡았다.

앞에서 Canvas와 TextMeshPro를 이용해 UI를 화면에 배치하고 정보를 표시하는 방법을 알아봤다면, Button과 UI Event는 사용자가 UI와 직접 상호작용하도록 만드는 기능이다.

Button은 사용자가 클릭해서 특정 기능을 실행할 수 있도록 하는 UI 요소이다.

게임에서 흔히 볼 수 있는 시작 버튼, 일시정지 버튼, 재시작 버튼 등이 대표적인 예시이다.

Unity에서는 Canvas 아래에 Button을 생성할 수 있고, Button 컴포넌트의 Inspector에서 `On Click()` 이벤트를 설정할 수 있다.

`On Click()`은 버튼이 클릭되었을 때 실행할 함수를 등록하는 이벤트이다.

예를 들어 게임을 시작하는 `StartGame()`이라는 함수를 만들고 Button의 `On Click()`에 연결하면, 사용자가 버튼을 클릭했을 때 해당 함수가 실행된다.

UI Event는 **사용자가 UI와 상호작용했을 때 발생하는 이벤트**를 의미한다.

Button을 클릭하는 것뿐만 아니라 Toggle의 체크 상태를 변경하거나 Slider의 값을 조절하는 것도 UI Event에 해당한다.

Unity에서는 이러한 이벤트가 발생했을 때 특정 함수가 실행되도록 연결할 수 있다.

Button의 클릭 이벤트를 연결하는 방법은 크게 두 가지가 있다.

**① Inspector에서 직접 연결하기**

Button 컴포넌트의 `On Click()` 항목에 스크립트가 부착된 GameObject를 등록하고, 실행할 함수를 선택하는 방법이다.

**② 코드에서 AddListener() 사용하기**

```csharp
button.onClick.AddListener(StartGame);
```

`AddListener()`를 사용하면 C# 코드에서 버튼의 클릭 이벤트와 함수를 연결할 수 있다.

두 방법 모두 버튼을 클릭했을 때 지정된 함수가 실행된다는 점은 같다.

### UI State & Game Logic

마지막으로 UI State & Game Logic은 **게임 내부의 상태 변화와 화면에 표시되는 UI를 연결하는 것**이다.

예를 들어 플레이어의 체력이 감소하면 체력 UI가 변경되고, 아이템을 획득하면 획득 개수가 갱신되는 방식이다.

게임에서 상태가 변경되더라도 UI가 갱신되지 않으면 사용자는 현재 상황을 파악하기 어렵다.

따라서 게임 로직에서 관리하는 데이터를 UI에 반영하는 과정이 중요하다.

## 4. 실습 과제: 기존 NPC에 데이터와 UI 연결하기

이번 과제에서는 지난 과제에서 구현했던 NPC의 FSM을 활용해 ScriptableObject와 UI를 구현했다.

새로운 행동을 추가하기보다는 **기존 NPC의 설정 데이터를 분리하고, 상태 변화를 화면에서 확인할 수 있도록 만드는 것**이 목표였다.

### 4-1. ScriptableObject로 NPC 설정값 관리하기

기존에는 NPC의 이동 속도나 공격 범위 등의 설정값을 `DuckFSM` 스크립트 안에서 직접 관리했다.

이번에는 이러한 설정값을 별도로 관리하기 위해 `DuckConfig`라는 ScriptableObject를 만들었다.

DuckConfig에는 NPC의 행동을 제어하기 위한 설정값을 저장했다.

대표적으로 이동 속도, 공격 범위, 회전 속도, 공격 지속 시간, 공격 쿨다운 등이 있다.

그리고 `DuckFSM`에서 DuckConfig를 참조하도록 변경했다.

```csharp
[SerializeField] private DuckConfig config;
```

이렇게 하면 NPC의 동작을 조절할 때 스크립트 내부의 값을 직접 수정하지 않고, Inspector에서 DuckConfig Asset의 설정값을 변경할 수 있다.

설정 데이터를 별도로 분리하니 NPC의 행동을 제어하는 코드와 설정값을 구분해서 관리할 수 있었다.

### 4-2. TextMeshPro로 NPC 상태 표시하기

다음으로 Canvas와 TextMeshPro를 사용해 두 가지 UI를 구현했다.

첫 번째는 **NPC의 현재 FSM 상태를 보여주는 UI**이다.

기존에 구현했던 NPC는 Idle, Wander, Attack 세 가지 상태를 가지고 있다.

- **Idle:** 가만히 대기하는 상태
- **Wander:** 플레이어를 향해 이동하는 상태
- **Attack:** 플레이어가 일정 거리 안으로 들어왔을 때 공격하는 상태

이번에는 NPC의 상태 변화를 화면 왼쪽 상단에 실시간으로 표시하도록 구현했다.

NPC가 대기하고 있을 때는 Idle, 플레이어를 향해 이동하면 Wander, 플레이어가 가까이 접근하면 Attack으로 표시된다.

이를 통해 NPC가 현재 어떤 상태인지 화면에서 바로 확인할 수 있게 되었다.

### 4-3. 플레이어와 NPC 사이의 거리 표시하기

두 번째는 **플레이어와 NPC 사이의 거리를 보여주는 UI**이다.

플레이어와 NPC의 위치를 이용해 거리를 계산하고, 그 결과를 TextMeshPro로 화면에 표시하도록 했다.

Unity에서는 `Vector3.Distance()`를 이용해 두 위치 사이의 직선거리를 계산할 수 있다.

```csharp
float distance = Vector3.Distance(
    player.position,
    transform.position
);
```

이렇게 계산한 값을 UI에 표시하면 플레이어가 NPC에게 가까이 다가가거나 멀어질 때 거리도 실시간으로 변경된다.

특히 NPC가 Attack 상태로 전환되는 시점과 거리 변화를 함께 확인할 수 있어 FSM이 의도한 대로 동작하는지 확인하기 편리했다.

### 4-4. 최종 구현 결과

최종적으로 기존 FSM에 ScriptableObject와 UI를 연결했다.

NPC는 플레이어를 향해 이동하며 거리를 좁히고, 일정 거리 안에 들어오면 공격 애니메이션과 폭발 이펙트를 실행한다.

화면 왼쪽 상단에서는 NPC의 현재 상태와 플레이어 사이의 거리를 실시간으로 확인할 수 있다.
